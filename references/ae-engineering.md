# AE 原生工程与逐帧复刻经验

本页适用于已经确定参考、素材和镜头表之后的 AE 实作、局部补丁与验收。
以下故障均来自实际工程排查；具体数值只是构造方法，不固定任何项目路径或镜头时长。
配套库为 `../scripts/ae_primitives.jsx`，加载只定义 `AEFrameTools`，不会打开或修改当前工程。

## 1. ExtendScript 与本机参数

- 按 ES3 编写 JSX：使用 `var`、普通函数和索引循环；不要假定支持现代数组方法、箭头函数或可选链。
- 本次宿主没有 `JSON.parse`。先探测；可携带兼容解析器，或仅对自己生成且受控的本地 receipt 使用 `eval('(' + text + ')')`。
- `eval` 是执行代码，不能用于网页内容、陌生附件或未经校验的外部 JSON。
- 用外部 Python/Node 生成 UTF-8 receipt；本机 JSX 只读取具体路径与预期值，不自己猜“最新工程”。
- 日志不要直接执行 `'position=' + array`；宿主的向量运算曾导致数值错误，即使前面的属性写入已成功。
- 用 `AEFrameTools.vectorText(values)` 明确逐项转字符串；错误日志须写目标名、操作、行号和是否保存。
- Node 语法检查只能排除语法问题；ES3 parser、mock 与真正 AE 渲染分别验证不同层次，不能互相替代。
- 使用经过现场确认的 matchName；局部补丁先验证目标 comp 唯一、层名唯一、层数和属性类型。
- 参数索引、角度意义、取值范围要在本机查询或短渲染验证，不能复制另一个插件版本的索引。
- 尤其颜色/不透明度范围可能分别为 0–1 和 0–100；不因界面显示百分号就自行推断内部范围。

## 2. 时间以整数帧为唯一来源

- 建立从0起的绝对帧表；镜头采用 `[startFrame, endFrameExclusive)`，长度为两者之差。
- 所有局部事件先记录整数帧，再由 `frame / fps` 转秒；不要不断累加小数秒来排镜。
- 23.976 等项目使用工程实际 frameRate；不能直接当24处理后再期待帧数相同。
- 一帧缩小、两帧剪影、三帧入场应逐格确认，不能被“整体节奏相似”覆盖。
- AE 图层 outPoint 是排他边界；两帧剪影应在本地帧k开始、k+2结束。
- 整段总帧数、各段帧数之和、实际导出帧数分别核对。
- 图片序列和视频的帧编号约定必须记录；不要把文件的0001直接当时间线第1帧。

## 3. 补关键帧时清理原来的运动

- 给旧属性追加几个新键，不会消除旧入场、回弹或延迟键；曾出现文字落稳后再左右抖动。
- 调用者先核对原生属性与整组新值是否匹配，再删旧键、完整重设目标属性；库会按可读取的property.value检查数字/字符串标量类型，以及数字向量的分量类型和长度。
- `setKeys(property, pairs, fps, interpolation)` 会拒绝重复帧和逆序帧，并在删除前完成输入检查。
- 基础检查还包括键对结构、整数帧、排序和数字有限性；2D/3D及颜色向量长度不符会在清键前拒绝，不自动丢分量或补Z。
- 这些检查不是完整宿主类型事务：property.value缺失或不可读取时跳过形状推断；Shape/TextDocument等复杂对象、原生取值范围仍由调用者验证。
- **时间重映射不适用通用clearKeys/setKeys**：删除最后一枚remap键可能关闭时间重映射；库按 `ADBE Time Remapping` 拒绝，调用者应保留端点直接setValueAtTime，或使用专门的remap重建流程。
- 库默认使用本机 `KeyframeInterpolationType.LINEAR`；一帧跳变明确传 `HOLD`。
- 清键不会自动移除表达式、父级动画、时间重映射或文本 Animator；仍有异常就检查这些来源。
- 该库拒绝覆盖启用表达式的属性；分离维度 Position 应分别传入 X/Y/Z follower。
- 空键数组表示只清键，不隐含设置新的静态值；需要静态终值时在调用后明确 setValue。
- 空间曲线、速度缓入缓出与切线需在设键后单独设置，不能因“已有几个键”假定运动平滑。
- 原生 setter 若中途失败，不要保存半成品；从该补丁的已保存输入重开，而非继续叠加未知状态。

```javascript
var position = layer.property('ADBE Transform Group').property('ADBE Position');
AEFrameTools.setKeys(position, [[0, [-600, 400]], [3, [92, 400]], [5, [80, 400]]], comp.frameRate);
// Replacement is idempotent: running again leaves exactly these three keys.
```

## 4. 大字、底片与透明度

- 避免文字和白底片作为独立3D层却处于几乎同一平面；近景Y旋转可能让底片遮字或交叉。
- 可先将词和底片都设2D、成对预合成，再把整个预合成作为一个3D面施加透视。
- 保留原有二维压缩、位置、转角、模糊；检查预合成边界是否裁掉字和投影。
- 字与底片共用一个3D父级不自动消除两个子层之间的深度排序问题；共同预合成更明确。
- 符纸、刀扇等前景物体仍可能遮住字尾；至少检查最大字号帧、透视近端及退出前最后可读帧。
- 首字近大与末字近大的Y旋转符号要看实际相机，不能仅凭数值正负判断。
- AE parenting 不会自动继承父级 Opacity；需要整体淡出时可操作共同预合成或明确写子层表达式。
- 若子层表达式读取 Null 的 opacity，创建 Null 后显式设100；不要依赖默认值，否则整组可能不可见。
- 同时检查父级是否被重复衰减，不要让两级 opacity 表达式把原定50%变成25%。
- 文本对齐表达式使用明确分支计算锚点系数；保持 `sourceRectAtTime` 的 left/top 偏移。
- 整词需要可读时保留原生 TextDocument 的完整字符串和空格；不要无条件逐字符拆开。

## 5. 固定人像窗口与剪影

- 先建立固定尺寸预合成/蒙版，再在内部安排人物的 anchor、scale 和 position。
- 外部窗口负责整体入场/旋转；内部人物负责小幅 pan/zoom；边框与外部窗口同步。
- 不要把蒙版直接绑定到一个独立缩放的立绘上，否则“固定框”会跟人物一起呼吸或漂移。
- 库的 `addFixedPortraitPanel(project, comp, source, options)` 仅在被调用时创建面板，并返回内外层。
- `options` 必填唯一name、整数width/height；可选center、durationFrames、focus、focusAt、zoom、borderWidth、borderColor。
- focus 是源图像素坐标，focusAt 是局部窗口像素坐标；zoom至少1，以cover比例为基础。
- 本辅助函数限制方形像素素材/合成；非方形素材先规范化，避免隐藏宽高比误差。
- `portraitPlacement` 限制初始位置不露出源矩形外部，但不识别透明像素，也不保证五官完整。
- 所以必须看人物眼嘴/头饰的真实范围，尤其绿底、透明留白和动态手袖不能只靠图片尺寸判断。
- 后续人物pan也要检查终点和中间最大位移；固定窗不会替你保持脸在安全区。
- 纯白/纯蓝剪影使用原图的独立实例或副本，只在这个剪影层上加Fill或等效颜色处理。
- 原彩色层保留；不要在共用人物预合成上永久加Fill，否则后续“恢复彩色”也会仍然是剪影。
- 灰阶对话图应按画面需要设置100%不透明度；“蒙灰”与“半透明”不是同一个操作。

## 6. 相机、模糊与画面边界

- AE 双节点相机的 Point of Interest 对应 Transform 中的 `ADBE Anchor Point`。
- 先确认是双节点相机及该属性可写；不要虚构一个 `ADBE Point of Interest` 属性名。
- 给相机 Position 与 POI 使用一致坐标空间，分别核对运镜、look-at和镜头开始/结束位置。
- 方向模糊、快门角和光学补偿参数必须渲一小段看方向；一次实际测试比注释可靠。
- 入场模糊不能把只有一两帧的关键造型全部涂掉；可单独关闭该层motionBlur，再手控短模糊。
- 模糊范围也可能越出预合成边界；把遮罩、效果扩展和主体移动一起检查。
- 全屏大圆环需要真正的全高合成；上下采样补色无法修补被短预合成切平的几何。
- 场景本来有黑色遮幅时应保留；不能把所有黑边一律补成背景颜色。

## 7. 唯一候选工程与串行补丁

- 每轮生成唯一candidate文件名，记录绝对路径、revision、帧数、主comp名及输入素材清单。
- 所有工程写入串行执行；不同AE会话可能各持旧状态，后保存者能覆盖先前已经成功的补丁。
- 一次补丁先读取自己生成的receipt，明确打开该candidate，不使用当前窗口名字或最近修改时间推断。
- 在写入前记录before：目标comp/层、属性、完整键数组和层数；条件不匹配就退出且不保存。
- 写入后读取after并核对；成功时保存到本轮唯一候选文件，记录实际 `app.project.file.fsName`。
- 关闭并重开这个文件，再读取同一组属性形成reopened快照；after与reopened相同才可交给渲染。
- 不要在尚有用户未保存编辑的另一个工程上自动close/open；先把补丁会话与工作会话区分清楚。
- 将确认后的唯一绝对路径写回receipt；后续aerender和审查脚本只使用该路径。
- 如果另存QA、DEPTH或局部渲染工程，记录从哪个revision派生，避免再次渲到旧分支。
- `beginUndoGroup` 有助于交互撤销，不是文件事务；日志SUCCESS也不能代替关闭重开验证。
- 配套库故意不提供自动保存/重开函数，以免加载工具时切换或覆盖用户工程。

## 8. 实际渲染与声音验收

- 先对修改区输出连续短片/序列，编号覆盖每一帧；不要只看首、中、尾三个静帧。
- 必须从新aerender输出重新提帧，报告精确文件路径与实际看过的帧范围。
- 补丁日志正确但画面没变时，比较前后相关帧hash并核对源工程；不要立刻继续修改构图数值。
- 相同hash可证明文件相同；不同hash只能证明变化，不能证明美术质量、可读性或运动已通过。
- 审阅落稳、离场和接镜，检查清楚后是否再次变糊、字尾碰撞、眼嘴出框、闪黑和重复启动。
- 问题只在新实际输出消失后关闭；报告中区分源码已修、保存已验证、实际画面已通过。
- 输出模块模板名称随安装/语言/用户配置变化；从本机 `outputModule.templates` 枚举后再选。
- 模板缺失不能 catch 后悄悄当成功；检查实际 Format、Channels、Audio Output 等可读设置。
- 检查音频素材 `hasAudio`、AV层 `audioEnabled`、层的入出点和最终输出是否包含音轨。
- 曾出现画面完成但所用模板关闭声音；必须用ffprobe检查最终文件的音频stream、时长和采样率。
- 有音频stream仍不等于有有效声音；检查静音段，并实际听开头、切点和结尾是否同步或截断。
- 若单独混音后封装，保持画面帧数和时间基准，明确音频来源，不额外复制或覆盖原工程。

## 9. 配套库的验证边界

- `frameToTime`、`fitScale`、`portraitPlacement`、`vectorText` 可在Node中纯函数测试。
- 用mock属性验证setKeys删掉旧键、正确换算帧时间、重复运行不累加、非法输入不先删数据。
- `addFixedPortraitPanel` 依赖AE原生对象；语法/mock通过不等于它在每个宿主版本都已运行验证。
- 在新环境先创建临时小合成测试面板、短渲染看框和人物，再用于正式镜头；测试不应自动保存正式工程。
