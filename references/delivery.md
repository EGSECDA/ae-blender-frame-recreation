# 保存、恢复和正式交付

## 单一工程写入者

并行代理可制作独立素材、脚本或审核不同连续区段；不要让多个进程打开同一个候选 AEP 后分别覆盖保存。后保存的旧内存状态可能覆盖已经成功保存的补丁，而各自日志都显示 SUCCESS。

推荐一次修订的交接记录包含：

```json
{
  "revision": "review-04",
  "parent_project": "project/review-03.aep",
  "candidate_project": "project/review-04.aep",
  "rendered_project": "project/review-04.aep",
  "rendered_picture": "renders/review-04.mov",
  "changes": [{"start_frame": 100, "end_frame_exclusive": 116, "reason": "caption clearance"}],
  "checked_ranges": [],
  "status": "awaiting-native-review"
}
```

使用唯一文件名，先完成写入并验证关闭重开，再更新当前候选记录。记录实际渲染的 AEP 路径及文件哈希。输出存在并不证明来自最新工程；若修正区域的帧与旧版完全相同，先核对保存后的参数、真实图层来源和渲染输入，再排查缓存。不要直接继续调数值。

## 后台程序恢复

保留构建脚本、素材清单、参数文件、原生日志和已经成功的帧。启动自己的后台进程时记录 PID、命令和输出目录；不要把进程名称相同的用户 GUI 会话一起结束。

失败先区分：脚本语法/版本 API、丢失素材、输出模板、内存、GPU、磁盘或应用崩溃。看最后成功帧与日志，再选择小范围复现、降低并发/分辨率、改用可用渲染设备或重启自己启动的进程。修复后从明确候选恢复，不覆盖已通过的交付文件。

相同配置反复失败不继续无限重启。一次重试没有新证据时，先收集错误和缩小测试；问题无法在现有权限/环境解决时，保存可恢复状态并明确缺项。用户未保存的 GUI 会话应先备份，不能为了脚本方便直接丢弃。

应用窗口控制失败与工程制作失败是两件不同的事。AEP 已成功构建并渲染、但 GUI 打不开时，交付文件和准确的窗口错误，不声称已在用户窗口中打开，也不以此否定已验证的文件。

## 透明序列合入 AE

记录序列编号从 0 还是 1 开始，以及对应主合成的哪一帧。确认解释帧率、尺寸、首尾帧、Alpha 类型和图层 startTime / inPoint / outPoint。Alpha 应由渲染结果决定是 Straight 还是 Premultiplied，不能只按扩展名推测。

前景深度层应放入同一段的色彩/光学预合成，使单帧倒色、整体模糊和退出影响全部相关素材。若蓝段与白段共享连续序列，白段时间偏移应接续前段，不能从序列第一帧重启。

## 输出检查

1. 原生 AEP：所需合成数量、总帧数、解释帧率、所有依赖文件、序列完整性、表达式错误、音频图层状态。字体替换和第三方效果要看实际渲染。
2. 原生画面：按审核记录覆盖所有需要检查的连续帧；改过的内容必须出现在新渲染中。自动差异、黑帧和高变化帧只用于定位，不能替代视觉判断。
3. 最终编码：重新全片解码；核对视频/音轨长度、帧数、尺寸、帧率、色彩与音量。片头片尾不能意外截断。
4. 画面沿用：若从已通过的中间母版复制视频流再合音，记录来源。H.264 重新编码后可以用全片 SSIM 定位损失或错帧；SSIM 是编码一致性证据，不是设计质量分数，也不拿它评判不同题材的改编质量。

本次本机 AE 的一个 ProRes 模板没有输出音轨，但这不是所有模板的通用规则。现场枚举/测试输出模板，检查实际输出是否含声音。只有确认配乐与工程混音等价，才可后期合入相同的音轨；不能静默丢掉 AE 中的音效、自动化或其他轨道。

## 文件结构与交接

按项目规模采用相应子目录，例如：`reference/`、`assets/`、`blender/`、`ae/`、`output/`、`review/`、`scripts/`。工程路径和渲染路径都写在交付记录中。用户要求全素材在项目目录下时，验证全部文件引用均在根目录内，序列每帧实际存在。

保留一个清楚的正式 AEP、播放 MP4、需要时的母版和 Blender 源文件入口；中间件放到单独目录。交付简要说明实际修改、核验范围及仍影响使用的限制，不把所有内部调试记录堆在最终回复中。
